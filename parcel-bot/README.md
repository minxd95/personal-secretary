# 택배 배송조회 텔레그램 봇

Node.js 24에서 실행되는 개인·지인용 배송조회 봇입니다. 관리자에게 승인된 사용자가 각자 텔레그램 1:1 채팅으로 택배를 등록합니다. CJ대한통운을 15분마다 조회하고 새 배송 이벤트를 알리며, 배송 완료 시 자동 조회를 종료합니다.

## 빠른 시작

```sh
cd parcel-bot # 저장소 루트에서 실행
npm ci
npm run setup
```

1. 텔레그램의 공식 **@BotFather**에서 `/newbot`으로 봇을 만듭니다.
2. `.env`의 `TELEGRAM_BOT_TOKEN`에 토큰을 직접 입력합니다. 토큰을 채팅이나 Git에 붙여 넣지 마세요.
3. 자신의 숫자 사용자 ID를 알고 있으면 `ADMIN_TELEGRAM_ID`에 입력합니다. 모르면 비워둔 채 `npm run pm2:start`로 실행하고, 새 봇의 1:1 채팅에서 `/whoami`를 보냅니다. 돌아온 ID를 `.env`에 입력한 뒤 `npm run pm2:restart`를 실행합니다. 관리자 ID가 없을 때는 ID 확인만 가능하며 첫 사용자를 자동으로 관리자로 지정하지 않습니다.
4. 관리자 계정으로 봇에 `/start`를 보냅니다. Telegram은 사용자가 먼저 시작하지 않은 대화에 봇이 메시지를 보낼 수 없습니다.
5. `/add cj 실제운송장번호 별명`으로 택배를 등록합니다.

토큰과 관리자 ID를 모두 입력했다면 바로 실행합니다.

```sh
npm run pm2:start
pm2 status parcel-bot
npm run pm2:logs
```

`npm run setup`은 기존 `.env`를 덮어쓰지 않고, 현재 Node 24의 실제 실행 경로를 `.node-path`에 기록합니다. fnm의 임시 셸 경로 대신 이 경로로 PM2가 봇을 실행합니다.

Ubuntu/Lightsail 서버로 이전하려면 [Ubuntu 배포 안내](docs/deploy-ubuntu.md)를 참고하세요. 같은 토큰으로 맥과 서버의 봇을 동시에 실행하지 않습니다.

## 맥 재부팅 후 자동 실행

PM2 실행과 부팅 시 PM2를 복구하는 설정은 별도 단계입니다. 기존 PM2 프로세스를 지우거나 `pm2 kill`, `pm2 delete all`을 실행하지 마세요.

```sh
# 현재 사용자에게 설정된 PM2 startup을 확인하고, 없으면 생성합니다.
pm2 startup launchd
# 위 명령이 sudo 명령을 안내하면 해당 명령을 본인 터미널에서 실행합니다.
# 정상 실행 중인 기존 프로세스와 parcel-bot의 목록을 저장합니다.
pm2 save
```

`pm2 startup`이 관리자 권한을 요청하는 이유는 macOS 부팅 서비스 등록 때문입니다. 토큰 없이 봇 연결을 완료할 수 없으며, startup 권한 명령도 사용자의 터미널에서 필요할 수 있습니다. 생성된 startup의 Node/PM2 경로가 `fnm_multishells` 같은 임시 경로를 가리키지 않는지 확인하세요. Node를 업그레이드하면 `npm run setup` 후 PM2 startup 경로도 갱신합니다.

PM2 공식 문서: https://pm2.keymetrics.io/docs/usage/startup/

- PM2 fork 모드 단일 인스턴스로 실행합니다. 같은 DB를 사용하는 다른 인스턴스는 잠금 파일로 거부합니다.
- 설정 오류(토큰 누락·잘못된 관리자 ID·기존 webhook 등)는 종료 코드 78로 멈춥니다. 설정을 수정한 뒤 재시작하세요.
- 네트워크 장애는 재시도하고, 비정상 종료는 PM2가 재시작합니다.
- **맥이 잠들거나 꺼져 있으면 조회할 수 없습니다.** 깨어나면 기한이 지난 택배를 한 번씩 조회합니다. 잠자는 동안 사이트에 쌓인 이력은 확인 가능한 범위에서 묶어 알립니다.
- 강제 종료나 전송 직후 연결 단절 시 Telegram의 수신 여부를 확정할 수 없어 알림이 재전송될 수 있습니다.

## 사용법

| 명령 | 설명 |
| --- | --- |
| `/start`, `/help` | 사용 신청 및 도움말 |
| `/add cj 123456789012 운동화` | 택배 등록 |
| `/add` | 택배사 → 번호 → 별명 순서로 등록 |
| `CJ 123456789012 운동화` | 명령어 없이 한 줄 등록 |
| `/list`, `/list all` | 추적 중인 목록 / 중지·완료 포함 전체 목록 |
| `/track [ID]` | 즉시 조회. 60초 이내 성공 결과는 재사용 |
| `/history [ID]` | 저장된 배송 이벤트 |
| `/rename ID 새별명` | 별명 변경 |
| `/pause [ID]`, `/resume [ID]` | 자동 추적·알림 중지 / 재개 |
| `/remove [ID]` | 삭제 확인 버튼 표시 |
| `/cancel` | 입력 취소 |
| `/status` | 내 택배 수, 최근 성공 조회와 오류 |
| `/whoami` | 자신의 숫자 Telegram ID |
| `/users` | 관리자: 신청·승인·차단된 사용자 목록 |
| `/approve ID`, `/block ID` | 관리자: 사용자 승인 / 거절·차단 |

`[ID]`는 `/list`에 나오는 `#1` 같은 등록 ID의 숫자 부분입니다. 생략하면 선택 버튼을 제공합니다. 한 줄 등록에서는 운송장번호를 하나의 토큰으로 입력하고, 번호 안에 공백이 있으면 `/add`의 단계별 입력을 이용하세요. 하이픈은 어느 방식에서나 제거됩니다. `cj`, `CJ대한통운`, `대한통운`을 지원하고, 별명은 100자까지입니다. 단계별 입력은 15분 후 만료됩니다.

사용자는 봇에서 `/start`로 사용을 신청합니다. 관리자에게 한 번만 승인·거절 버튼을 전송합니다. 신청자는 승인될 때까지 다른 기능을 사용할 수 없습니다. 관리자 ID는 `.env`로만 변경할 수 있습니다. 차단된 사용자의 명령과 배송 알림은 중단되며, 기존 등록은 보관됩니다. 관리자가 재승인하면 추적을 재개합니다.

## 조회와 저장 동작

- CJ 공식 사이트의 세션 쿠키와 CSRF 토큰으로 조회합니다. 제3자 배송조회 서비스 가입은 필요하지 않습니다. 공개된 계약형 API가 아니므로 사이트 변경 시 연동 수정이 필요합니다. 접근 제한이나 CAPTCHA를 우회하지 않습니다.
- CJ 페이지·조회 요청 사이에 최소 2초를 두며 조회를 직렬화합니다. 한 운송장의 수동·자동 요청이 겹치면 공유합니다.
- 운송장 미등록은 정상적인 대기 상태입니다. 전송 오류나 응답 구조 변경은 별도 오류로 기록합니다.
- 조회 실패는 1분부터 최대 1시간까지 간격을 늘려 재시도하며 서버의 Retry-After를 우선 존중합니다. 연속 3회 실패 시 한 번, 복구 시 한 번 안내합니다.
- 배송 단계가 같아도 시각·위치·설명이 달라 새 이벤트가 생기면 알립니다. 응답 순서 변화나 동일 이벤트의 반복은 알림을 만들지 않습니다. 알 수 없는 새 상태 코드도 보존합니다.
- 여러 사용자가 같은 운송장을 등록하면 조회와 배송 이벤트를 공유합니다. 사용자별 별명, 목록, 읽은 이벤트, 중지·삭제 여부는 분리합니다.
- 중지 중에는 자동 조회가 필요 없는 경우 요청을 보내지 않습니다. 다른 사용자가 같은 택배를 추적하면 수집한 이벤트를 저장하며 재개 후 알려줍니다. 중지 전 이미 예약된 알림도 재개 후 전달합니다. 수동 `/track`은 중지 중에도 가능합니다.
- 완료 알림을 DB에 저장한 뒤 자동 조회를 끝내므로, 알림 전송이 실패해도 나중에 재전송됩니다. 완료 택배는 `/list all`, `/history`로 확인하고 `/remove`로 삭제합니다.
- SQLite에 명령 처리 위치, 단계별 입력, 수동 조회 작업과 발송 대기 알림을 저장합니다. 재시작해도 이어서 처리합니다. 상태 변경과 알림 예약은 같은 트랜잭션으로 저장합니다.
- 목록·이력·명령 버튼은 모든 요청마다 소유자를 검사합니다. 그룹 채팅은 처리하지 않습니다.

## 운영 설정

| 환경변수 | 기본값 | 의미 |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | 필수 | BotFather에서 발급한 토큰 |
| `ADMIN_TELEGRAM_ID` | 비어 있음 | 관리자 계정 ID. 미설정 시 설정 모드 |
| `DATABASE_PATH` | `./data/parcel-bot.sqlite` | SQLite 파일 경로 |
| `POLL_INTERVAL_MINUTES` | `15` | 기본 조회 간격, 1~1440분 |
| `CJ_REQUEST_GAP_MS` | `2000` | CJ 요청 간 최소 간격, 2000ms 이상 |
| `REQUEST_TIMEOUT_MS` | `15000` | CJ 요청 타임아웃 |

화면 시간은 항상 Asia/Seoul 기준입니다. `.env`, DB, 로그, 로컬 Node 경로는 `.gitignore`에 포함됩니다. DB에는 운송장번호와 배송 이력이 저장되므로 비공개로 보관하세요. 콘솔에는 토큰, 전체 조회 응답, 운송장번호를 출력하지 않습니다.

```sh
npm run pm2:restart  # 빌드 및 설정 재적용
npm run pm2:stop     # 자동 조회 중지
npm run pm2:logs     # 로그 보기
npm start           # PM2를 중지한 뒤 포그라운드 실행
npm run dev         # 개발용 빌드 및 포그라운드 실행
```

PM2가 이미 실행 중인데 `npm start`를 동시에 실행하면 DB 잠금 오류가 발생합니다. 프로세스가 없다는 것을 확인하기 전 잠금 파일을 삭제하지 마세요. 로그는 `logs/`에 기록되므로 장기 운영 시 용량을 확인하고 PM2의 로그 회전 설정을 적용할 수 있습니다.

DB를 안전하게 백업하려면 `npm run pm2:stop` 후 `data/` 디렉터리 전체(SQLite의 WAL·SHM 파일 포함)를 복사하고 재시작하세요. 복원할 때도 봇을 먼저 중지합니다. DB 스키마는 `PRAGMA user_version`으로 관리합니다.

## 검증

```sh
npm test
npm run check
npm run verify:pm2  # 별도 PM2_HOME에서 실제 진입점·재시작 검증, 모든 네트워크는 모의 응답
npm run smoke:cj -- 본인의실제운송장번호
```

자동 테스트는 외부 서비스에 메시지를 보내지 않고 CJ/Telegram 응답을 주입합니다. 권한 검사, 관리자 승인, 명령 재처리, 단계별 입력, 조회 공유·캐시, 이벤트 중복 제거, 실패·복구 알림, 알림 재시도, DB 트랜잭션 롤백과 재시작 복구를 확인합니다.

`smoke:cj`는 실제 CJ 서버에 요청하며, 번호나 배송 설명을 출력하지 않고 조회 성공 여부·상태·이벤트 개수만 출력합니다. 실제 변경 알림의 최종 검증은 본인의 진행 중인 운송장을 등록해 수행하세요. 테스트 운송장이나 웹에 공개된 타인의 운송장으로 검증하지 마세요.

## 다른 택배사 추가

`src/domain.ts`의 `Carrier` 인터페이스를 구현하고 `TrackingService`에 전달하는 택배사 목록에 등록합니다. 번호 정규화·검증과 조회 응답을 `TrackingResult`/`DeliveryEvent`로 변환하는 책임을 택배사 모듈 안에 둡니다. 이벤트 key는 순서·조회 시각에 영향을 받지 않도록 만듭니다. 세션·HTTP 호출 제한도 각 모듈에서 처리합니다. 새로운 모듈의 응답 fixture와 상태 매핑 테스트를 함께 추가합니다.
